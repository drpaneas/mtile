# Host PGO — kept for cmd/mtile only

One frozen 30-second training profile improves the actual `Service.Build` Go
preparation prefix by **6.05%**, saving **0.900 ms per three-project held-out
corpus**. All six actual-method paired samples improved; neither control exceeded
the predeclared 2% regression limit. The retained profile is
[`cmd/mtile/default.pgo`](../../../../cmd/mtile/default.pgo). Existing production
Go source and modules are unchanged; no editor profile was installed.

This covers source loading/bundling, globals analysis, validated asset loading
and flattening, transpilation, renderer metadata and linked-asset checks. It ends
before workspace creation and external TinyGo compilation. Whole CLI latency,
native frame rates and editor rendering were not timed.

## Fixed inputs and measured boundary

The training corpus was Celeste AUTO, Multi-file and Audio GB Song, visited once
each per round. The sole profile collected **1,509 rounds** in a 30-second loop
(30.14 seconds including profile shutdown). Held-out projects were Platformer,
Pong and Mapdemo; independent controls were Hello and Noalloc Call Stress. No
held-out input contributed profile samples, and no profile tuning followed the
measurements.

The previously planned Celeste Mode 0 project fails its current baseline renderer
guard. Celeste AUTO instead passes and selects Mode 4 with a source-positioned
`circfill` fallback. The planned Loop holdout fails `MAP_EXPLICIT_CONTRACT`, even
with explicit Mode 4. These substitutions were preflighted and fixed before
profiling; [original checks](preflight-results.json) and
[replacement checks](preflight-heldout-replacement.json) are preserved. No example
source or renderer rule changed.

| Held-out project | Invocations per corpus | Bundled Lua bytes | Generated Go bytes | Share of Lua / generated bytes |
| --- | ---: | ---: | ---: | ---: |
| Platformer | 1 | 158 | 20,985 | 2.59% / 2.97% |
| Pong | 1 | 4,343 | 79,685 | 71.14% / 11.29% |
| Mapdemo | 1 | 1,604 | 605,353 | 26.27% / 85.74% |

Platformer is a small starter. Each corpus operation gives equal invocation
counts, while Mapdemo dominates generated byte volume. These volume shares are
not measured time weights; no individual-project timing was added. The result
applies to this fixed mix, rather than a broad sample of large games.

All eight source/asset trees were copied under
`/tmp/mtile-go-weekly-loop/pgo/inputs`. The ignored local Celeste project is fully
preserved there, with only its [SHA manifest](input-manifest.json) in the
repository. All **136 frozen input files** remained unchanged through validation.
The initial and measured source snapshots and hashes are retained separately.

## Original test-only preparation experiment

The private helper mirrors `Build` through the pre-workspace boundary, including
default Service settings, project renderer selection, source/global metadata,
the SourceFiles clone, nil-Trace formatting, project IWRAM functions, asset
prevalidation, `assetsync.Load`'s single flatten, optional Mode 0 text overlay,
source-remapped diagnostics and final linked-asset validation. Hashing and
verification occur outside timing. There is no new public Prepare API.

Both binaries were compiled from one frozen source tree with either `-pgo=off`
or the one explicit profile. The helper's generated source and metadata were
checked against actual `Build`, stopping after `writeWorkspace` and before
TinyGo. Complete output manifests hash generated Go, assets, sources, project,
globals, renderer report and linked audio size. Those manifests matched exactly
across off/trained binaries for all eight projects.

The run used Go 1.27.1, darwin/arm64 on Apple M2 Pro, normal GC, warm filesystem
caches and the unchanged host default **GOMAXPROCS=12**. After discarded warmups,
ten pairs alternated off/trained order; each benchmark used a 1-second Go
benchmark duration. Median comparison gates were at least 3% held-out improvement
and no greater than 2% slowdown for either control.

| Mirrored prefix | Off median ms/op | Trained median ms/op | Change | Improved pairs |
| --- | ---: | ---: | ---: | ---: |
| Held-out corpus | 15.309107 | 14.616669 | −4.523% | 10/10 |
| Hello | 0.910899 | 0.890560 | −2.233% | 9/10 |
| Noalloc Call Stress | 0.421933 | 0.397113 | −5.882% | 8/10 |

This first gate passed, saving 0.692 ms per held-out corpus. Raw sample CV was
5.84%/6.31% for the held-out baseline/trained runs and 7.76–10.20% for controls.
Every held-out pair nevertheless improved, by 2.62–7.06%. These host timings are
not deterministic cycle measurements. [Raw samples](samples.json),
[summary](summary.json), [metadata](metadata.json), profiles and logs are retained.

## Actual production-method deployment validation

PGO can optimize the mirrored caller differently from the production method, so
passing the first gate and matching outputs were insufficient for deployment.
An additional append-only test fixture calls the actual `Service.Build` method
and stops via its Trace callback at `PhaseWorkspace`. The same callback and one
panic/recover boundary are included in both variants. No workspace or TinyGo work
occurs inside the benchmark. This small harness overhead is explicit.

Separate binaries from a separate source copy preserve the original binaries,
hashes and sample history. The profile, inputs, CPU settings and optimization
flags did not change. Six alternating pairs applied the same **3% held-out / 2%
control** rules; there was no second profile or repeated helper benchmark.

| Actual Build prefix | Off median ms/op | Trained median ms/op | Change | Improved pairs |
| --- | ---: | ---: | ---: | ---: |
| Held-out corpus | 14.872283 | 13.972378 | **−6.051%** | 6/6 |
| Hello | 0.882836 | 0.844215 | −4.375% | 6/6 |
| Noalloc Call Stress | 0.394987 | 0.395299 | +0.079% | 3/6 |

The actual-method held-out gain was 4.01–10.65% in individual pairs. Raw sample
CV was 1.51%/1.36% for the held-out runs and 0.42–1.05% for controls. All gates
passed. [Actual-method samples](actual-samples.json),
[summary](actual-summary.json) and [binary/profile metadata](actual-metadata.json)
retain the evidence.

| Actual Build prefix | Off → trained median B/op | Off → trained median allocs/op |
| --- | ---: | ---: |
| Held-out corpus | 17,205,073.5 → 17,200,390 | 105,682 → 105,223.5 |
| Hello | 908,033 → 907,783.5 | 6,479.5 → 6,403.5 |
| Noalloc Call Stress | 400,189 → 399,611 | 2,977 → 2,885 |

Fractional counts are medians of integer benchmark samples, not fractional
allocations. Memory savings are small; the useful result is reduced preparation
time with bounded controls.

## Actual command, cost and maintenance

The command was built once with `-pgo=off` and once with automatic use of
`cmd/mtile/default.pgo`. Its build metadata explicitly records that profile path.
The host executable grew **231,408 bytes**, from 7,374,434 to 7,605,842 bytes
(**3.14%**). The profile itself is **48,300 bytes**. Test-binary growth was
231,456 bytes and is not the shipping binary cost.

The real off/default CLI executables produced identical generated Go and ROM
hashes for Hello (25,100 bytes), Pong (70,708 bytes) and Mapdemo (195,508 bytes).
[CLI validation](cli-validation.json) records hashes and retained workspaces.
No external TinyGo timing claim is made. Scoped build/CLI tests and full runtime
suites in both render modes passed; the parent experiment loop owns the final
full root suite. [Preservation audit](production-preservation.json) verifies all
581 pre-existing source/module files unchanged.

The gain justifies retaining this small command-specific profile, with explicit
maintenance limits. The mirrored helper must track build-prefix changes; its
untimed actual-Build parity checks and actual-method validation guard that risk.
The training corpus includes an ignored local project, so a clean checkout
cannot reproduce the exact profile without that fixture or its preserved
snapshot. A changed fixture, substantial compiler/pipeline change, or Go upgrade
requires a new declared experiment; do not silently substitute inputs or claim
the old gain. Automatic training and editor-wide profiling are not installed.

The [refresh recipe](../../../../scripts/go-weekly/pgo/README.md) preserves the
one-profile rule and validation steps. To opt out for a command build:

```sh
go build -pgo=off -o build/mtile ./cmd/mtile
```
