# Γιατί ο στατικός χάρτης χρειάζεται διαφορετική δουλειά από τον παίκτη

Ο παίκτης αλλάζει θέση σε κάθε update. Το έδαφος, αφού αφαιρεθούν τα markers
των αντικειμένων στο `_init`, παραμένει ίδιο. Ο προηγούμενος Mode 4 renderer
ξαναδιάβαζε τα tiles και τα pixels τους σε κάθε `map(1)`. Άρα επαναλάμβανε
δουλειά της οποίας το αποτέλεσμα ήταν ήδη γνωστό.

Η αλλαγή γίνεται μέσα στο mtile· ο κώδικας του παιχνιδιού συνεχίζει να καλεί
`map(1)` με ακριβώς την ίδια σημασία.

## Πώς φτιάχτηκε

1. Μετά το `_init`, όσο η οθόνη είναι ακόμη σβηστή, ο runtime μετατρέπει τον
   χάρτη σε έναν πίνακα αρχικών χρωματικών δεικτών. Έτσι περιλαμβάνει και τις
   αλλαγές `mset` που αφαίρεσαν τα markers.
2. Σε κάθε γραμμή καταγράφει τις συνεχόμενες περιοχές που έχουν αδιαφανή
   pixels. Τα διάφανα κενά παραλείπονται: δεν πρέπει να σβήσουν σύννεφα ή άλλα
   γραφικά που σχεδιάστηκαν πίσω από το έδαφος.
3. Στα επόμενα frames αντιγράφει αυτές τις περιοχές στον framebuffer. Για τον
   πλήρη χάρτη χωρίς μετατόπιση, μία μικρή ARM ρουτίνα στην IWRAM επεξεργάζεται
   όλη τη λίστα. Οι `LDMIA`/`STMIA` μεταφέρουν τέσσερις καταχωρητές, δηλαδή
   16 bytes, ανά ομάδα. Τα λίγα αρχικά/τελικά pixels κάθε περιοχής γράφονται
   χωριστά, ώστε να διατηρούνται τα διπλανά διάφανα pixels.
4. Για screen shake, clipping ή υποπεριοχές παραμένει η γενική διαδρομή
   αντιγραφής. Αν η μετατόπιση δεν είναι πολλαπλάσιο τεσσάρων, συνδυάζει δύο
   ευθυγραμμισμένες λέξεις με shifts. Ο ARM7TDMI δεν διαβάζει μια αυθαίρετα
   μη ευθυγραμμισμένη λέξη με τη σημασία που θα περιμέναμε από έναν σύγχρονο
   επεξεργαστή, επομένως η ευθυγράμμιση ελέγχεται ρητά.

Δεν χρησιμοποιήθηκε DMA ανά μικρή περιοχή. Εδώ υπάρχουν πολλά μικρά τμήματα
και διάφανα κενά· η μία κλήση ARM για όλη τη λίστα αποφεύγει το επαναλαμβανόμενο
κόστος κλήσης Go και επιτρέπει ακριβείς εγγραφές στην EWRAM.

## Πότε χρησιμοποιείται και πότε όχι

Η αυτόματη βελτιστοποίηση αφορά Mode 4, έναν αποθηκευμένο χάρτη έως 30×20 tiles,
αμετάβλητο spritesheet, χωρίς map streaming. Ο transpiler δεσμεύει buffers μόνο
αν ο υπολογισμός της μνήμης του συγκεκριμένου target τους χωράει. Στον υπολογισμό
περιλαμβάνονται Context, globals του παιχνιδιού, asset RAM και ο native audio
controller όταν υπάρχει. Κρατά ολόκληρο τον χώρο των δύο Lua heaps και επιπλέον
8 KiB περιθώριο. Αν δεν χωρούν, τα arrays έχουν μήκος μηδέν και χρησιμοποιείται
ο κανονικός renderer. Το παλιό software audio profile εξαιρείται.

Για τον χάρτη 240×160 το κόστος είναι 38.400 bytes pixels και έως 2.048 εγγραφές
των 4 bytes: συνολικά **46.592 bytes / 45,5 KiB EWRAM**. Δεν γίνεται δυναμική
κατανομή μνήμης κατά το draw. Αν ένα πολύ κατακερματισμένο σχέδιο χρειάζεται
περισσότερες περιοχές, η προετοιμασία εγκαταλείπεται με ασφάλεια και διατηρείται
ο παλιός renderer.

Η γρήγορη διαδρομή δέχεται την identity draw palette, μόνο το χρώμα 0 ως
διάφανο και map calls χωρίς ενεργό flag mask. Άλλο `pal`, `palt` ή mask
χρησιμοποιεί τον παλιό ακριβή κώδικα. Ένα πραγματικό `mset` ακυρώνει το cache·
μια εγγραφή της ίδιας τιμής δεν το ακυρώνει. Τα `pal()`/`palt()` resets δεν
χρειάζεται να ξαναφτιάξουν τα αρχικά pixels. Δεν άλλαξε δημόσιο Lua API ούτε
η επιλογή renderer.

## Πώς ελέγχθηκε

Ο host έλεγχος συγκρίνει κάθε pixel της γρήγορης διαδρομής με την προηγούμενη
υλοποίηση, πάνω σε μη ομοιόμορφο ήδη σχεδιασμένο υπόβαθρο. Περιλαμβάνει 900
τυχαίους συνδυασμούς camera, clip, υποπεριοχών και διαφορετικών logical BGs,
αλλαγές palette/transparency, masks, `mset`, επανεκκίνηση Context και overflow
της λίστας. Επιπλέον ελέγχθηκαν στενοί χάρτες 1/3/17/29/30 tiles, όλες οι
ευθυγραμμίσεις οριζόντιας μετατόπισης και μη ευθυγραμμισμένο buffer.

Ο κώδικας ARM ελέγχθηκε ξεχωριστά στο native mGBA: δημιουργούνται δύο ROMs με
ίδια assets και κώδικα, με cache ενεργό και ανενεργό. Το SHA-256 ολόκληρου του
RGBA frame πρέπει να συμφωνεί. Συμφώνησε και στις πέντε περιπτώσεις:

| Camera | Draw χωρίς cache | Draw με cache |
| --- | ---: | ---: |
| 0, 0 | 551.878 cycles | 167.744 cycles |
| 0, 1 | 548.690 cycles | 235.557 cycles |
| 1, 1 | 660.510 cycles | 316.189 cycles |
| 2, 1 | 654.631 cycles | 315.524 cycles |
| 3, 1 | 648.748 cycles | 314.267 cycles |

Οι χρόνοι είναι διάμεσοι μετά το warm-up και περιλαμβάνουν το `cls(0)` του
fixture. Δεν είναι ο συνολικός χρόνος ολόκληρου του παιχνιδιού. Σε αντίστοιχο
έλεγχο ολόκληρου του παιχνιδιού, η διαφορά με/χωρίς `map(1)` ήταν περίπου
102.000 cycles, έναντι περίπου 481.000 πριν από την αλλαγή. Η βελτίωση του
χάρτη από μόνη της δεν αποδεικνύει ότι όλες οι σκηνές χωρούν στο frame budget.

Οι εντολές επανάληψης, από τη ρίζα του repository:

```sh
go test ./internal/transpiler -run TestMapRaster
(cd runtime && go test ./...)
go run examples/celeste/tests/map_raster_probe.go
go run examples/celeste/tests/performance_probe.go full no-map
```

Η πρώτη native σύγκριση της τελικής έκδοσης αποθηκεύτηκε στο προσωρινό
`celeste-map-raster-3395118396`. Το probe γράφει πάντα τον νέο φάκελο evidence
και το hash/κόστος κάθε ROM, ώστε τα αποτελέσματα να μπορούν να αναπαραχθούν.

## 6 Σεπτεμβρίου: λιγότερη δουλειά όταν τρέμει η κάμερα

Το screen shake μετακινεί το terrain κατά λίγα pixels. Αυτό χαλούσε την κοινή
ευθυγράμμιση πηγής και προορισμού, ενώ η αντιγραφή γινόταν με ξεχωριστή κλήση
Go για κάθε αδιαφανή περιοχή. Η νέα ARM ρουτίνα επεξεργάζεται ολόκληρη τη λίστα
με μία κλήση, εφαρμόζει το ίδιο clipping και κρατά όλες τις διάφανες τρύπες.

Για μετατόπιση ενός, δύο ή τριών bytes χρησιμοποιεί αντίστοιχη διαδρομή με
σταθερά shifts. Ο ARM7TDMI εκτελεί αυτά τα shifts οικονομικότερα από τα shifts
των οποίων το μέγεθος διαβάζεται από καταχωρητή. Κάθε επανάληψη γράφει δύο
λέξεις και κρατά την τελευταία λέξη της πηγής για την επόμενη επανάληψη.
Τα λίγα pixels στα άκρα αντιγράφονται χωριστά, μέσα στα ίδια όρια.
Επειδή κάθε γραμμή τελειώνει σε όριο τεσσάρων bytes, η τελευταία πλήρης λέξη
μπορεί επίσης να χρησιμοποιήσει ευθυγραμμισμένη ανάγνωση χωρίς να βγει από τη
γραμμή. Έτσι απομένουν μόνο 0–3 μεμονωμένες εγγραφές στο τέλος κάθε περιοχής.

Η αλλαγή προσθέτει 556 bytes κώδικα IWRAM και καθόλου EWRAM. Αφορά χάρτες
πλάτους 240 pixels· οι στενότεροι διατηρούν την υπάρχουσα γενική διαδρομή.

| Camera | Πριν | Μετά |
| --- | ---: | ---: |
| 0, 1 | 235.557 cycles | 183.381 cycles |
| 1, 1 | 316.189 cycles | 227.497 cycles |
| 2, 1 | 315.524 cycles | 226.868 cycles |
| 3, 1 | 314.267 cycles | 225.331 cycles |

Πρόκειται για το ίδιο fixture με `cls(0)`. Η κάμερα χωρίς μετατόπιση κρατά
ουσιαστικά το ίδιο κόστος. Δεν αλλάξαμε ούτε το πλάτος ούτε τη διάρκεια του
shake για να πετύχουμε τη βελτίωση.

Για verification έγιναν 15 native συγκρίσεις ολόκληρου framebuffer με τον
παλιό renderer: θετική/αρνητική κάμερα, όλες οι ευθυγραμμίσεις, clipping,
υποπεριοχές και pixels στα όρια. Το υπόβαθρο περιέχει διαφορετικά χρώματα,
ώστε να φαίνεται αν γράψουμε κατά λάθος μέσα σε διάφανο κενό. Όλα τα hashes
συμφώνησαν. Πέρασε επίσης όλο το runtime test suite.

```sh
go run examples/celeste/tests/map_raster_probe.go parity
```

Το συγκεκριμένο evidence γράφτηκε στο `celeste-map-raster-459864821`.
Ο παραγωγικός ROM εξακολουθεί να χωράει στη μνήμη και πέρασε το native stress
χωρίς heap corruption ή audio overflow. Η συνολική επίτευξη του frame budget
εξακολουθεί να χρειάζεται έλεγχο μετά την ενσωμάτωση των υπόλοιπων βελτιώσεων.
